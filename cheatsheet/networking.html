Model OSI 7 Layer vs Model TCP/IP

Kerangka teoritis konseptual transmisi data melalui jaringan komputer.

7 Lapisan Model OSI (Urutan dari Atas ke Bawah) Fundamentals
7. Application: Interaksi antarmuka pengguna (HTTP, HTTPS, FTP, DNS, SMTP).
6. Presentation: Translasi format data, kompresi, dan enkripsi (TLS, SSL, JPEG, ASCII).
5. Session: Manajemen inisiasi, pemeliharaan, dan terminasi sesi koneksi antar aplikasi.
4. Transport: Pengiriman data end-to-end dengan segmentasi dan flow control (TCP, UDP). Unit: Segment.
3. Network: Pengalamatan logis (IP Address) dan perutean (Routing) antar jaringan. Unit: Packet (Router).
2. Data Link: Pengalamatan fisik (MAC Address) dan deteksi error di jaringan lokal. Unit: Frame (Switch).
1. Physical: Transmisi sinyal biner mentah melalui media fisik (kabel fiber, tembaga UTP, radio WiFi). Unit: Bits.
Jembatan Keledai Populer: "All People Seem To Need Data Processing" (7 → 1).

Subnetting & Notasi CIDR

Rumus menghitung jumlah host yang dapat digunakan dan menentukan Network & Broadcast IP.

Rumus Jumlah Usable Host: 2^(32 - Prefix) - 2 Calculation

Mengapa dikurangi 2? Karena 1 alamat dicadangkan untuk Network ID (alamat pertama) dan 1 untuk Broadcast (alamat terakhir).

Prefix CIDR Subnet Mask Total IP Usable Hosts

/25 255.255.255.128 128 126
/26 255.255.255.192 64 62
/27 255.255.255.224 32 30
/28 255.255.255.240 16 14
/30 255.255.255.252 4 2 (Point-to-Point Link)

Rentang IP Privat (RFC 1918)

Alamat IP lokal yang tidak dirutekan ke internet publik dan membutuhkan NAT untuk keluar.

3 Kelas IP Privat Standar Dunia Standards
Kelas A: 10.0.0.0 s/d 10.255.255.255 (Prefix: 10.0.0.0/8 - 16 juta host untuk enterprise besar).
Kelas B: 172.16.0.0 s/d 172.31.255.255 (Prefix: 172.16.0.0/12 - 1 juta host).
Kelas C: 192.168.0.0 s/d 192.168.255.255 (Prefix: 192.168.0.0/16 - jaringan rumah & kantor kecil).
Loopback (Localhost): 127.0.0.1 s/d 127.255.255.255 (Traffic tidak keluar kartu NIC).
APIPA (Link-Local): 169.254.0.0/16 (Otomatis dipakai jika perangkat gagal mendapatkan IP dari server DHCP).

TCP vs UDP & 3-Way Handshake

Perbandingan dua protokol transport layer yang menggerakkan internet.

TCP 3-Way Handshake & Karakteristik Protocols
Tahap 1: Client mengirim paket flag SYN (Synchronize).
Tahap 2: Server membalas paket SYN-ACK (Synchronize & Acknowledge).
Tahap 3: Client membalas paket ACK (Acknowledge) → Koneksi resmi terjalin (Established).
TCP: Reliable, connection-oriented, ada penomoran paket (sequencing), retransmisi jika paket hilang (cocok untuk Web, Email, File transfer).
UDP: Fast, connectionless, tidak ada retransmisi atau overhead handshake (cocok untuk Video Streaming, Voice VoIP, Online Gaming, DNS queries).

Network Diagnostic CLI Tools

Perintah terminal esensial untuk memeriksa konektivitas dan routing.

Perintah Troubleshooting Jaringan CLI
# Uji konektivitas dan latency menggunakan paket ICMP ping -c 4 8.8.8.8 # Lacak jalur router yang dilewati paket (hop-by-hop) traceroute google.com # (Linux / Mac) tracert google.com # (Windows) # Cek port yang sedang listening di server Linux ss -tulpn # Modern Linux (menggantikan netstat) # Query DNS resolver detail dig google.com +short nslookup -type=MX github.com
