Arsitektur & Komponen Kubernetes

Memahami peran Control Plane (Master) dan Worker Node dalam orkestrasi container.

Control Plane vs Worker Node Architecture

Pembagian peran komponen sistem dalam cluster Kubernetes.

kube-apiserver: Titik masuk (entry point) seluruh komunikasi dan perintah REST/kubectl.
etcd: Distributed key-value store konsisten penyimpan seluruh state dan konfigurasi cluster.
kube-scheduler: Memilih worker node yang optimal untuk menempatkan Pod baru.
kube-controller-manager: Memastikan keadaan riil cluster sesuai dengan *desired state* (ReplicaSet, Node lifecycle).
kubelet (Worker): Agen lokal di setiap worker node yang memastikan container berjalan sesuai PodSpec.
kube-proxy (Worker): Mengatur network rules (iptables/IPVS) untuk routing service.

Objek Inti: Pod, Deployment & Service

Blok pembangun utama aplikasi terdistribusi di Kubernetes.

Deployment Manifest (YAML) Manifest

Mengatur replikasi Pod, rolling update deklaratif, dan auto-healing.

apiVersion: apps/v1 kind: Deployment metadata: name: api-backend labels: { app: api } spec: replicas: 3 selector: matchLabels: { app: api } template: metadata: labels: { app: api } spec: containers: - name: web image: nginx:alpine ports: [{ containerPort: 80 }]
Service Types (ClusterIP vs NodePort vs LoadBalancer) Networking

Mekanisme mengekspos sekumpulan Pod dengan IP statis dan load balancing internal/eksternal.

ClusterIP (Default): Hanya bisa diakses dari DALAM cluster. Cocok untuk database atau internal microservice.
NodePort: Membuka port spesifik (range 30000-32767) pada setiap worker node IP publik.
LoadBalancer: Mengintegrasikan Load Balancer resmi cloud provider (AWS ELB, GCP Cloud LB) dengan IP publik stabil.
Ingress: Layer 7 (HTTP/HTTPS) reverse proxy routing berbasis domain (misal: api.example.com vs app.example.com).

Perintah kubectl Esensial

Koleksi perintah CLI yang wajib dihafal untuk inspeksi, modifikasi, dan operasional cluster.

Inspeksi Status Cluster & Objek Inspection
# Lihat daftar Pod di seluruh namespace kubectl get pods -A -o wide # Deskripsi detail status & event penyebab Pod error kubectl describe pod -n # Pantau perubahan status Pod secara live kubectl get pods -w
Debugging: Logs & Masuk ke Container Debugging
# Streaming logs container secara realtime kubectl logs -f --tail=100 # Lihat log dari container yang crash sebelumnya (wajib hafal!) kubectl logs --previous # Masuk ke terminal interaktif di dalam Pod kubectl exec -it -- /bin/sh # Forward port Pod ke localhost tanpa ekspos service kubectl port-forward pod/ 8080:80

Health Probes & Resource Limits

Menjamin ketahanan aplikasi dan mencegah Pod rakus memonopoli resource worker node.

Liveness vs Readiness Probe & Limits Resilience
resources: requests: { memory: "256Mi", cpu: "250m" } # Alokasi minimum yang dijamin limits: { memory: "512Mi", cpu: "500m" } # Batas maksimal (melebihi ini -> OOMKilled) livenessProbe: httpGet: { path: /healthz, port: 8080 } initialDelaySeconds: 15 periodSeconds: 10 # Gagal -> Pod di-RESTART oleh kubelet readinessProbe: httpGet: { path: /ready, port: 8080 } periodSeconds: 5 # Gagal -> Pod DILEPAS dari traffic Service (tidak di-restart)

Troubleshooting Kasus Error Populer

Penyebab dan solusi status error yang paling sering ditanyakan saat live debugging.

CrashLoopBackOff & OOMKilled Error Handling
CrashLoopBackOff: Container dijalankan lalu crash berulang kali. Solusi: Cek dengan kubectl logs <pod> --previous atau kubectl describe pod <pod> untuk melihat exit code aplikasi / salah variabel env.
OOMKilled (Exit Code 137): Container melebihi memory `limits` yang ditetapkan pada YAML. Solusi: Tingkatkan memory limits atau benahi memory leak aplikasi.
ImagePullBackOff / ErrImagePull: Nama image salah, tag tidak ditemukan di registry, atau credential secret private registry belum dikonfigurasi (`imagePullSecrets`).
Pending: Pod belum bisa dijadwalkan ke node mana pun karena node kehabisan CPU/RAM (Insufficient cpu/memory) atau node selector/taints tidak cocok.

Quick Reference Perintah kubectl

Tabel ringkasan sintaks kubectl untuk referensi cepat.

Perintah Sintaks Kegunaan
Apply Manifest kubectl apply -f manifest.yaml Deploy / update konfigurasi deklaratif
Describe Object kubectl describe <kind> <name> Inspeksi riwayat Events dan error detail
Previous Logs kubectl logs <pod> -p Lihat log container sebelum mati/restart
Scale Replicas kubectl scale deploy api --replicas=5 Tambah / kurangi jumlah Pod secara manual
Rollback Deploy kubectl rollout undo deploy/api Kembalikan deployment ke versi sebelumnya
Drain Node kubectl drain <node> --ignore-daemonsets Kosongkan node sebelum maintenance/upgrade
