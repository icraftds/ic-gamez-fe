Git & GitHub Cheatsheet

Panduan praktis sistem kontrol versi (Version Control System). Menguasai alur staging, percabangan cabang fitur, penyelamatan saat salah commit, resolusi merge conflict, hingga standar penulisan pesan commit profesional.

Kategori 01

Setup & Konfigurasi Awal

Identitas Pengguna (Name & Email)

Mengatur identitas kontributor yang akan melekat pada setiap riwayat commit.

git config --global user.name "Nama Lengkap"
git config --global user.email "email@domain.com"
Kategori 02

Alur Kerja Harian (Daily Routine)

git status, add & commit

Siklus kerja paling sering digunakan: memeriksa berkas yang berubah, memasukkan ke area penampungan (staging), dan merekam snapshot permanen.

git status  # Cek berkas berubah
git add .  # Stage semua berkas
git commit -m "feat: pesan commit yang jelas"
git diff & git log

Melihat perbedaan baris kode sebelum di-commit (git diff) dan melihat riwayat commit ringkas berbentuk diagram pohon cabang (git log --oneline --graph).

git log --oneline --graph --decorate -n 10
Kategori 03

Percabangan (Branching)

Membuat & Berpindah Branch

Perintah modern untuk membuat cabang baru sekaligus langsung berpindah ke cabang tersebut.

git switch -c feature/nama-fitur  # Cara modern Git 2.23+
git checkout -b feature/nama-fitur  # Cara lama universal
Kategori 04

Merge vs Rebase: Perbedaan Vital

KarakteristikGit MergeGit Rebase
Riwayat CommitNon-destruktif: membuat commit baru bertipe "Merge commit", riwayat cabang tetap bercabang.Linear & Rapi: memindahkan titik pangkal cabang ke ujung target, riwayat lurus seperti satu garis.
Kapan Digunakan?Menggabungkan fitur yang sudah tuntas ke cabang utama (main / develop) untuk mempertahankan histori.Menyelaraskan cabang fitur pribadi dengan cabang utama terbaru sebelum membuat Pull Request.
Perintahgit merge feature/namagit rebase main
Golden Rule of Rebase: Jangan pernah melakukan rebase pada cabang publik (seperti main yang digunakan bersama tim) karena akan menulis ulang riwayat commit!
Kategori 05

Git Stash (Simpan Sementara Tanpa Commit)

git stash, pop & list

Menyimpan pekerjaan koding yang belum selesai ke tempat penyimpanan sementara (laci tersembunyi) saat harus mendadak berpindah cabang untuk memperbaiki bug lain.

git stash -u      # Simpan termasuk untracked files
git stash pop     # Kembalikan pekerjaan dan hapus dari laci
git stash list    # Lihat daftar pekerjaan tersimpan
Kategori 06

Membatalkan Perubahan (Reset vs Revert)

Perbedaan Reset (--soft, --mixed, --hard) vs Revert
PerintahApa yang Terjadi pada Berkas Anda?Aman di Remote?
git reset --soft HEAD~1Membatalkan commit terakhir, berkas tetap tersimpan di area Staging.Lokal saja
git reset --mixed HEAD~1Membatalkan commit dan staging, berkas tetap ada di folder kerja (Unstaged).Lokal saja
git reset --hard HEAD~1BAHAYA: Menghapus commit dan seluruh perubahan kode secara permanen!Lokal saja
git revert HEADAMAN: Membuat commit baru yang membalikkan efek dari commit sebelumnya.Sangat Aman untuk Remote
