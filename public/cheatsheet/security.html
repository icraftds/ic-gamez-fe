OWASP Top 10 Overview

Katalog risiko keamanan aplikasi web terpenting yang wajib dipahami oleh seluruh Software Engineer.

Top 5 Kerentanan Paling Kritis Risk Assessment
A01: Broken Access Control: Pengguna bisa mengakses data milik user lain hanya dengan mengganti ID pada URL (IDOR - Insecure Direct Object Reference). Solusi: Cek ownership dan izin otorisasi di server pada setiap request.
A02: Cryptographic Failures: Password disimpan dalam plain-text atau hash usang (MD5/SHA1), atau data sensitif dikirim via HTTP tanpa enkripsi TLS.
A03: Injection: Input pengguna disisipkan langsung ke interpreter SQL/NoSQL/OS tanpa sanitasi (SQL Injection, Command Injection).
A04: Insecure Design: Cacat arsitektur sejak awal desain sistem (misal: fitur lupa password yang tidak membatasi percobaan brute force).
A05: Security Misconfiguration: Port database terbuka untuk internet (0.0.0.0/0), pesan error database lengkap dibocorkan ke browser client, atau kredensial default admin/admin belum diubah.

SQL Injection, XSS & CSRF

Mekanisme serangan paling sering muncul dalam wawancara kerja developer.

SQL Injection (SQLi) & Parameterized Queries Vulnerability

Peretas menyuntikkan perintah SQL jahat ke kolom input pencarian atau form login.

// VULNERABLE KODE (JANGAN PERNAH GUNAKAN STRING CONCAT!): const query = `SELECT * FROM users WHERE email = '${req.body.email}'`; // Jika input: ' OR '1'='1' -- -> Peretas bisa login tanpa password! // SECURE KODE (Prepared Statements / Parameterized Query): const query = 'SELECT * FROM users WHERE email = $1'; await db.query(query, [req.body.email]); // Parameter diperlakukan murni sebagai teks statis
Cross-Site Scripting (XSS) Client-side

Penyusupan skrip JavaScript jahat ke browser korban untuk mencuri cookie sesi atau membajak akun.

Stored XSS: Script jahat disimpan permanen di database (misal pada komentar blog) dan dieksekusi setiap kali user lain membuka halaman.
Reflected XSS: Script jahat disisipkan lewat parameter URL query (?search=<script>...</script>) dan langsung dipantulkan di respons server.
Mitigasi: Gunakan HTML Entity Encoding (escape karakter <, >, ", '), terapkan header Content-Security-Policy (CSP), dan simpan token sesi pada HttpOnly cookies.

JWT Security & Safe Session Cookies

Menyimpan dan memvalidasi identitas pengguna dengan aman di sisi client dan server.

Mengapa JANGAN Simpan Token Sensitif di LocalStorage? Best Practice

Kelemahan fatal LocalStorage dan alternatif cookie yang aman.

Masalah LocalStorage: Dapat dibaca oleh kode JavaScript apa pun di halaman. Jika website terkena sedikit celah XSS, peretas bisa langsung menjalankan localStorage.getItem('token') dan mencuri seluruh sesi!
Solusi Rekomendasi: Simpan Access/Refresh Token di HttpOnly, Secure, SameSite=Lax Cookie. Cookie ini mustahil dibaca oleh JavaScript client-side melalui serangan XSS.
Set-Cookie: session_id=xyz789; HttpOnly; Secure; SameSite=Strict; Path=/; Max-Age=86400

HTTP Security Headers Wajib

Instruksi langsung ke browser untuk mengaktifkan perlindungan bawaan.

4 Security Headers Paling Penting Hardening
Content-Security-Policy (CSP): Membatasi domain mana saja yang boleh mengeksekusi script, image, dan koneksi API. Sangat ampuh mencegah serangan XSS.
Strict-Transport-Security (HSTS): Memaksa browser berkomunikasi HANYA melalui HTTPS aman, mencegah serangan SSL Stripping.
X-Frame-Options: DENY: Mencegah website Anda dibungkus ke dalam <iframe> oleh situs lain (mencegah Clickjacking).
X-Content-Type-Options: nosniff: Mencegah browser menebak (MIME-sniffing) tipe file selain dari header Content-Type yang dideklarasikan.

Kriptografi: Hashing vs Enkripsi

Salah satu pertanyaan jebakan paling populer dalam wawancara kerja teknis.

Hashing vs Enkripsi (Perbedaan Kunci) Theory
Hashing (Satu Arah): Mengubah data sembarang ukuran menjadi digest berukuran tetap. TIDAK BISA didekripsi kembali. Digunakan untuk verifikasi password (contoh: bcrypt, Argon2id).
Enkripsi (Dua Arah): Mengacak data plaintext menjadi ciphertext menggunakan kunci rahasia. BISA didekripsi kembali dengan kunci yang sesuai (contoh simetris: AES-256; asimetris: RSA).
Salt: String acak unik yang ditambahkan ke password sebelum di-hash untuk menggagalkan serangan Rainbow Table pratebak.
